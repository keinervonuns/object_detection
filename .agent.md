# PI Detection — Agent Guide

## Project Overview

**PI Detection** is a multi-class image-classification system with real-time
camera inference. It is a single PyTorch pipeline at the repository root:

collect images → split train/val → train → live inference, with GradCAM +
OmniXAI explainability, region masking, and 4-bit GPIO LED output for a
Raspberry Pi.

---

## Pipeline (repository root)

Stack: PyTorch + Torchvision, EfficientNet-B0/B2 or ResNet-50 backbones, NVIDIA
RTX A2000 with mixed-precision (AMP), real-time camera inference with GradCAM,
OmniXAI (GradCAM + LIME HTML reports), region masking, MixUp + augmentation,
early stopping + best-checkpoint saving.

| File | Purpose |
|------|---------|
| `config.py` | **Central configuration** — CLASSES, training params, paths |
| `setup_data.py` | `--init` creates `source/<class>/`; no flag splits into `data/train` & `data/val` |
| `train.py` | Trains on the split → `models/best_model.pth` (+ curves / report / history) |
| `run.py` | ★ Entry point — real-time inference + GradCAM + GPIO LEDs. `--no-gpio` disables LED output. Keys: `g` GradCAM, `s` save, `e` region edit, `r` reset FPS, `h` help, `q` quit. In region edit mode: arrows move the border, `s` toggles expand/shrink, `z` undoes, `c` resets |
| `capture_images.py` | Webcam tool for collecting training images into `source/<class>/` |
| `tests/test_camera.py` | Camera sanity check (index / resolution) |
| `tests/test_led.py` | LED wiring test — `--mode single` (GPIO 17) or `--mode binary` (values 0–15) |
| `requirements.txt` | Python dependencies |

The full user guide lives in the repo-root `README.md` (English) and
`README.de.md` (German) — environment setup per machine, training, model
transfer, and running detection.

Notable behaviour:

- `CLASSES` in `config.py` maps class name → 4-bit LED number (0–15). The same
  dict drives `capture_images.py` class cycling and `run.py` LED output; a
  class absent from it outputs `0`.
- Detection region = rectangle in `regions/region_config.ini`, edited at runtime
  with `e` + arrow keys and saved on exit. Outside the region is dimmed and
  zeroed before inference.
- `run.py` opens the camera at index 0, MJPG, 1920×1080 (V4L2 on Linux, the
  platform default elsewhere) and uses the frame size it reports as the region
  default. The region rectangle is clamped to the real frame size on load and on
  every frame. Inference preprocessing mirrors `train.py`'s validation transform
  (shorter edge → `IMG_SIZE * 1.15`, then a centre crop), so any camera
  resolution is framed like the training data.
- Paths are relative to the script/`config.py`, so scripts can be run from any
  working directory.

### Environment

- Virtual environment lives at `venv/` in the project root (git-ignored).
  Python 3.10+ on the training PC; Python 3.13 (system `python3`) on the Pi.
- Training runs either on a GPU machine (Windows/Linux, e.g. RTX A2000) or
  locally on the Pi's CPU (`BACKBONE = "efficientnet_b0"`, `BATCH_SIZE = 8`).
  For inference the Pi only needs `models/best_model.pth` copied over.
- `run.py --no-gpio` disables the GPIO LED output. With GPIO enabled it
  initialises `RPi.GPIO` **before** importing torch/cv2 (importing them first can
  interfere with GPIO setup), and adds `venv/lib/python*/site-packages` to
  `sys.path`, so `sudo python3 run.py` gets `RPi.GPIO` from the system and
  `torch`/`cv2` from the venv.

### Common workflows

```bash
cd <project-root>          # the folder that holds config.py

# One-time setup
python -m venv venv && source venv/bin/activate   # Windows: venv\Scripts\Activate.ps1
pip install -r requirements.txt                    # + pip install "omnixai[vision,plot]" (optional)

# Train
python setup_data.py --init          # create source/<class>/ folders
#   → drop images into each source/<class>/
python setup_data.py                 # split into data/train + data/val
python train.py                      # train → models/best_model.pth

# Infer — on the Pi:  sudo python3 run.py
#          on the PC:  python run.py --no-gpio

# Hardware checks
python tests/test_camera.py
python tests/test_led.py --mode binary
```

Key config values (`config.py`): `BACKBONE` (`resnet50` / `efficientnet_b0` /
`efficientnet_b2`), `BATCH_SIZE` (32; lower if VRAM is tight), `NUM_EPOCHS` (50),
`EARLY_STOP` (8), `LABEL_SMOOTHING` (0.1), `MIXUP_ALPHA` (0.2), `NUM_WORKERS`
(4; set 0 on Windows), `USE_AMP` (True on the A2000).
